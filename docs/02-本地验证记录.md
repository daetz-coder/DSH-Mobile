## 测试结果：dsh-pocket 自带测试

59 项通过，3 项失败——**均为 Windows 环境差异，非代码缺陷**（本仓库未改动上游代码）：

| 失败测试 | 原因 |
|---|---|
| `resolveCloudflared：手动放置的资产名文件也能命中缓存（issue #15）` | Windows 上 `cloudflared-windows-amd64.exe` 资产名与 bin 名 `cloudflared.exe` 的映射分支与上游 macOS 预期不同 |
| `公网隧道自动恢复：关闭后删除标记（issue #11）` | 标记文件删除时序在 Windows 文件系统下慢于测试假设的 60ms |
| `WSL 局域网 IP（issue #39）：detectWsl` | 本机 Windows Terminal 注入 `WSLENV=WT_SESSION:WT_PROFILE_ID:`，`detectWsl()` 误判为 WSL 环境（上游测试假定 macOS 无该变量） |

> 说明：`detectWsl` 的误判不影响实际使用——局域网 IP 探测在 Windows 直接跑 `ipconfig.exe`，与 WSL 检测分支无关；但二开时若需精确 WSL 判定，应改为同时校验 `WSL_INTEROP` 或 `/proc/version` 内容。

## 端到端打通（2026-08-25 晚）

手机 App 成功显示电脑端 DSH Web 完整界面（会话列表 / 模式徽标 / 模型 / 进行中任务）。

联调中定位并解决的三个关键问题：

1. **WebView 禁止跨域 iframe 的 autofocus 与表单提交** → dsh-pocket 验证页的
   PIN 输入在 iframe 内无法聚焦/提交（`input` 键盘不弹、`requestSubmit()` 无网络请求）。
   解决：新增 `AuthBridgePlugin`——原生层 POST `/pocket-login`，捕获 302 会话
   cookie 并写入 WebView CookieManager，同时返回 token 供 `?token=` URL 认证。
2. **`AndroidKeyStore` GCM 加密禁止调用方提供 IV**（`setRandomizedEncryptionRequired`
   默认 true）→ `SecureStorePlugin.set()` 改为 `cipher.init(ENCRYPT_MODE, key)`
   让 Keystore 自生成 IV，再 `getIV()` 存密文。
3. **局域网 PIN 开关默认开启** → 关闭 `~/.dsh/dsh-pocket/settings.json`
   `lanAuthEnabled: false`（注意：PowerShell `Set-Content -Encoding UTF8` 会写
   BOM 导致 JSON.parse 失败，必须用无 BOM UTF8——本项目已踩坑）。

> ⚠️ 安全权衡：关闭局域网密码后，同一 WiFi 内任意设备可访问本机 DSH（可执行代码）。
> 仅个人自用网络可接受；公网隧道不受影响（始终要求密码）。如需恢复：
> 删除 `settings.json` 或设 `lanAuthEnabled: true`，重启 dsh web。

> 注意：以上「关闭局域网 PIN」的记录是早期联调阶段的临时动作；后续恢复为
> `lanAuthEnabled: true`（安全默认），App 已支持 PIN 自动化流程（见下文）。

## 公网隧道验证（2026-08-25）

- 独立 CLI `dsh-pocket --public --port 3082` 建立 cloudflared 隧道：
  cloudflared 自动下载（GitHub 多镜像）→ 快速隧道 URL 生成。
- 手机 `curl https://<随机>.trycloudflare.com/` → HTTP 200、完整 DSH 页面。
- 结论：**公网链路（4G/任意网络 → 隧道 → 电脑代理 → DSH）技术可行**。
- 注意：独立 CLI 隧道默认无 PIN（`bin/dsh-pocket.mjs` 未配置 auth）；dsh web
  内置插件（：3081）隧道则有公网 PIN + 每次轮换。App 对公网 URL 的配对
  同一流程（check → PIN/token → 整页导航）。
